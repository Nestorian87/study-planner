# Reusable Notion template

Two installation paths: duplicate the separate clean native Notion template, or recreate from assets/notion-template.json through connected Notion tools. This is NOT an Artifact Template Gallery format. Native public duplication requires the owner to deliberately publish only the clean copy and enable duplication; never publish the personal hub as a side effect.

## Recreate from files
1. Read Notion Markdown and view DSL docs. Ask for/resolve an authorized destination, or create a private draft. Resume from the saved destination manifest instead of creating duplicate systems after a timeout.
2. assets/notion-template.json contains four schemas, page content and view definitions. Assets use symbolic `courses`, `plans`, `tasks`, `opportunities` keys, not actual workspace IDs. Map simple types: text → RICH_TEXT, title → TITLE, number → NUMBER, date → DATE, checkbox → CHECKBOX, url → URL, last_edited_time → LAST_EDITED_TIME. Select options retain names/colors; status options retain names/colors/groups. Quote identifiers and literals safely.
3. Create courses and plans, then tasks and opportunities. For relations substitute the newly returned collection IDs. A relation with `reverse` uses DUAL with that name. Defer task self-relation until tasks exists, then add it. Never use original/source IDs. Check schema/view state after each operation and persist IDs to private config/notion.local.json.
4. Seed is optional: assets/coursework-example.json retains eight sample course names and 29 originally unfinished works. It intentionally omits previously ready/submitted/credited work and every diploma milestone; it is not a complete generic curriculum. The recipient can remove/add courses and works. All seeded tasks start До виконання, courses have effort Невідомо. Don't copy personal rules allowing other groups, instructor identities, group IDs, dates, target periods, participant names, progress, history or current plans.
5. Seed courses before tasks, bind each task's course key to the new page URL. Use stable example keys to avoid duplicate retries. Set Архів false. Other personal fields stay unset; unchecked defense is not evidence of no required defense.
6. Add views using the new data-source IDs. Fetch each database first, configure its default view with a short visible column list (technical fields hidden), then add listed views. Native linked views on the hub are sufficient; no paid charts required. Keep short headings, no decorative prose.
7. Check every relation target and every linked view belongs to the new template, not the source personal hub. Read courses/tasks/plans/opportunities using default saved views where possible to verify seed counts and no finished states, dates, personal context or test rows. Check source personal counts are unchanged.
8. Native duplication into a different workspace needs a recipient-side smoke check: new relation targets, view references, self-relation and settings/config. Notion export CSV cannot reconstruct relation properties by import. Source templates and file blueprint are separate from the recipient's actual canonical data.

## Installing skill
Copy this complete skill folder to the recipient's personal Codex skills directory, or use a project-scoped skill installation supported by their Codex. Don't copy the original user's config, data caches, source Git history, legacy application or installed symlink. Bind fresh IDs. Configure effort categories without demanding per-task times. The CIST adapter is optional and specific to NURE; another university needs its own source adapter.
